# MCP pair fixture

This fixture models write admission against a bounded in-memory inbox while retaining the SDK `mcp` transport/session interfaces and the SDK `jsonrpc.EncodeMessage`/`DecodeMessage` codec path. Each inbox has a first-terminal-commit ownership contract: under that inbox's mutex, the first close that commits terminal state records an immutable owner. A later write returns `io.EOF` when its writer owns that terminal state, and `io.ErrClosedPipe` when another connection owns it. If the writer's close bit is set before the destination terminal is committed, the write returns `io.EOF`. This is commit ordering per inbox, not wall-clock ordering of `Close` invocation. Already-admitted write/encode failures and queued read/decode failures keep their original errors.

The tests retain the publication barrier and bounded asynchronous close-worker joins as evidence for owned-close, peer-close, and both terminal-commit orderings. This fixture is not an SDK `net.Pipe`/`ioConn`, SDK decoder, fragmentation, or batching test. It does not replace RawSDK observation, real-HTTP/native controls, or original runtime assertions; production `Close`/`Wait` behavior is outside this fixture and untouched.
