# Process-local expensive KDF admission

This cooperative admission guard permits at most one held password-KDF batch in a process. `Acquire` waits with a nonnil context; `TryAcquire` returns immediately when occupied. Every successful admission returns an idempotent release closure. A delayed/double release cannot free a later owner's lease. Cancellation after a lease is returned does not revoke it: an active Argon workspace must finish before release, or another workspace could overlap.

The existing SSH `keyfile.masterKey` now acquires once around its complete four-derivation batch and releases on success/error. Its contextless API waits with `context.Background`, preserving signatures and return semantics rather than introducing busy failures. Application-store master derivation must use the same guard when implemented. Current production Argon2id calls were inspected and flow through this master path; direct tiny-profile derivations in tests remain independent test oracles. Per-layer HKDF operations and AES encryption are not expensive-password admission batches.

This is scheduling-only coordination: passphrase rules, salt generation, all four independent Argon2id parameters/order/outputs, HKDF domains and 1000 AES data layers are unchanged. Existing encrypted bytes, readers/writers, container versions, cached master lifecycle and SSH public interfaces are unchanged. Contending unlocks may now wait; fairness or a new wall-clock deadline is not promised for the existing contextless SSH API.

The guard is process-local, not a host-wide memory cap, OS sandbox, authorization mechanism or guaranteed workspace erasure. Other processes or KDF code bypassing it are not controlled. A caller must not release early or forget release. Waiting caller count and the application-store two-operation budget remain higher-level responsibilities. No passphrases, keys, salts, profiles, operation data or credentials are cached here.

Tests cover immediate exclusivity, old/concurrent double release, cancellation before/waiting/after admission, and subsequent acquisition. The SSH integration witness synchronously attempts `TryAcquire` inside every fake derive callback; it must fail for all four callbacks and the permit must be available after success/error. This witness does not rely on scheduler delays or timeout-based absence. Tests were authored but not executed locally; public GitHub CI and existing wire/production-profile vectors supply execution evidence. Local work ran formatting only.
