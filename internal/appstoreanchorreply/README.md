# Signature-checked anchor reply metadata

This isolated package checks the proposed fixed reply in `docs/application-store/IO.md`. `Verify` requires exactly 352 bytes, a supplied nonzero 32-byte Ed25519 public key, and expected operation/request/store IDs. It copies inputs, verifies Ed25519 over bytes 0..288 exactly, then checks `SSASRSP1`, correlation and every reserved byte. Operation is exactly Read=1, CreateIfAbsent=2 or CAS=3; request/store IDs are mandatory and nonzero.

The closed outcome table admits ReadState/Rejected/Unknown/NotFound for Read, and Committed/Conflict/Rejected/Unknown for mutations. Stateful outcomes require length 192, canonical scoped `appstoreanchorstate` bytes and the exact binary-domain state hash. Empty outcomes require zero length, slot and hash. NotFound requires service version zero. Successful creation requires exact genesis and version zero; successful CAS requires positive service version. No optional fields, trailing bytes or fallback are admitted.

`Reply` keeps private copied metadata; arrays and State are returned by value. The zero Reply is not signature-checked; every error returns it and opaque `ErrInvalid`, never partial metadata. `SignatureValid` means only that the supplied key verified these bytes and that their encoding/correlation passed. It does not establish where that key came from, whether the expected request was sent, human enrollment, service/credential identity, an authenticated TLS session, anti-replay, freshness, revocation, linearizability or durability.

The protocol still requires independently enrolled service keys and per-store credentials, authenticated transport/role binding and correct client history. A signature replay under an old expected request is not detected here. Service version is returned as metadata, not compared to a prior trusted version; recorded idempotent mutation results may legitimately precede a later current state. This verifier does not compare a mutation's resulting state to an independently durable intent or claim that a recorded operation outcome is the latest state. NotFound is not permission to recreate an already enrolled store. Unknown/Conflict must not be turned into commit or automatic replay. Those policies and read-first reconciliation remain outside this package.

Canonical state admission does not verify the complete journal prefix, nonce uniqueness, reservation confirmation, retained-object history, snapshot AEAD tags or plaintext. Signed malicious-writer/service state is not made safe here. There is no network client, CAS, writer, recovery action, KDF, encryption, secret-byte release, MCP tool or authority token. SSH and the mandatory four sequential independent 1-GiB Argon2id derivations/1000 AES layers are unchanged.

Synthetic keys and independently constructed reply/state bytes cover the complete outcome table, every-byte signature tampering, wrong keys/correlation, re-signed malformed padding/slots/hashes/states, creation/version rules, bounds and copy ownership. Malformed semantic fixtures are re-signed so signature rejection cannot mask missing validation. Tests were authored but not executed locally; public GitHub CI supplies execution evidence. Local work ran formatting only.
