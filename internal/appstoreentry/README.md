# appstoreentry

Linux-only protected storage for the encrypted installation binding used by task236's initial local trusted-install ceremony. The CLI requires an existing absolute, private (`0700`) directory. `Open` traverses without following symlinks, validates the directory and lock, and acquires a nonblocking exclusive lock. `Install` creates `binding.bin` exclusively, syncs and reads it back; `Load` bounds and validates it. `VerifyUnchanged` checks the pinned directory identity, binding inode, and ciphertext digest before sensitive actions. Renaming the same directory preserves device/inode identity; copying it to a different inode does not. Non-Linux builds fail closed; callers should check `Supported` before prompting.

This local installation ceremony depends on independent human verification of the existing store ID and preprovisioned service, root CA, signing key, and TLS writer credentials. It neither provisions a production service role nor performs enrollment, and cannot cryptographically prove the external source or human identity. The binding is separate from snapshots. It has four independent sequential 1-GiB Argon2 operations and 1000 data-encryption layers. This package does not implement RAM secret-source handling or composition with appstorefile. Go-owned memory clearing is best-effort; host swap, runtime, and root compromise are outside scope.

The current CLI `put` workflow is first-entry only and refuses any store with an existing committed snapshot, rather than replacing its catalog. It does not support multi-object updates or merging. Tests are authored but not executed; public CI and the final full gate are pending.
