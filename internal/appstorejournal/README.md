# Application-store journal commitments

This isolated package implements the entry encoding and prefix-commitment prerequisite from `docs/application-store/IO.md`. It does not append, sync, truncate, reserve, create an anchor, perform CAS, generate IDs, encrypt, deliver bytes or establish authority. The expected `appstoreanchorstate.State` is structurally admitted, not authenticated by this package.

`Entry` is exactly 40 bytes: unsigned big-endian uint64 index, snapshot ID[16], transaction ID[16]. `ParseEntry` requires the exact expected index below 2^20 and nonzero IDs. `NewEntry` constructs the same bytes only. Fields are private and array accessors return copies; zero Entry is invalid. `NextHead` computes exactly `SHA256(ASCII("SSAPP-JOURNAL-ENTRY-v1") || store_id || previous_head || entry_bytes)`, without NUL or other separators. It requires nonzero store/previous head and an admitted Entry. This hash helper does not prove that the supplied previous head is authentic or that the entry belongs at that point.

`InspectPrefix` starts at the canonical store-bound genesis head and consumes exactly `expected.JournalCount()` entries, requiring indices 0..count-1 and the exact expected final head. It retains no entry list and allocates no count-sized history; one 40-byte input buffer and fixed-size hash inputs are used. Returned `Prefix` contains copied store/state hash, head, count and consumed-byte metadata only. `Valid` means commitment matching, not verified service identity, authorization, nonce uniqueness or a confirmed reservation.

No EOF probe is performed: bytes after the expected prefix, even a partial crash suffix, remain unread. Count zero consumes no bytes. A caller must separately discover, chain-check, reconcile and permanently quarantine ciphertext associated with suffix entries according to the full protocol; never infer absence, truncate, encrypt or commit merely because this prefix matches. This package also does not detect duplicate snapshot/transaction IDs across history or prove a candidate absent from every anchored/retained object. Those freshness checks remain required separately.

`ErrInvalid` rejects inconsistent, truncated or mismatching input; `ErrUnavailable` covers nil/no-progress readers and non-EOF I/O failure, including an error returned with a complete entry. All errors return zero metadata without raw I/O details. Neither error proves on-disk corruption or authorizes repair/deletion/replay. Readers must obey `io.Reader`; a blocked reader needs caller-enforced deadlines/cancellation. No hard wall-clock bound, filesystem identity or source immutability is promised.

Authenticated human enrollment, secure transport, durable linearizable service replies, history/uniqueness, exclusive ownership, suffix handling and two-phase commit/fencing remain outside this package. Signed or hash-matching malicious-writer state is not made safe here. Four independent sequential 1-GiB Argon2id derivations, 1000 AES layers, SSH interfaces and deny-only production MCP are unchanged.

Independent entry/chain vectors, malformed/index/order/hash/scope cases, truncation, short and bounded reads, maximum-count early EOF, operational errors, copy ownership and preservation of untrusted suffixes are covered by authored tests. Local work ran formatting only; public GitHub CI supplies execution evidence.
