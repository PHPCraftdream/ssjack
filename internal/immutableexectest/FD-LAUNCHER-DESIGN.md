# Linux amd64 sealed launcher: descriptor inheritance design

Status: design proposal only. No production integration is authorized or implied; this is not a security proof or sandbox.

## Repository evidence and scope

`internal/immutableexec/immutableexec_linux.go` binds a digest-checked static ELF image into a sealed memfd, then starts `/proc/self/fd/3` through Go `os/exec`, with the memfd in `ExtraFiles`. Its README warns unrelated descriptors are not audited/guaranteed closed and says there is no production launch integration. `docs/declarative/driver.md` specifies direct execution, fixed empty environment, exact enrolled identity, and trusted drivers (not sandboxes). Existing Runner's configurable limited environment is a discrepancy to resolve before integration.

## Required ABI and kernel policy

Target only Linux x86-64, ELF64 little-endian `ET_EXEC`, no interpreter/dynamic sections, matching the existing static ELF validator. Native launcher ABI is amd64 Linux syscall convention; use `close_range(2)` and `execveat(2)`, no shell or PATH. Require Linux 5.11 minimum: `close_range` was introduced in 5.9 and `CLOSE_RANGE_CLOEXEC` in 5.11; require `CLOSE_RANGE_UNSHARE` (5.9). At runtime any `ENOSYS`, `EINVAL`, `EPERM`, resource failure, or other syscall error aborts. No procfs or close-loop fallback. Backports must pass the actual operations; version strings are insufficient.

## Input contract and trust boundary

The repository's current `os/exec` route is not a realizable implementation of the following transition as written. It starts the target image directly; adding a launcher executable first creates a separate exec boundary. At that boundary, ordinary inherited `FD_CLOEXEC` source descriptors disappear, while Go `os/exec` deliberately maps `ExtraFiles` into child descriptors (and does not make the arbitrary other descriptors an explicit allowlist); non-CLOEXEC arbitrary descriptors are inherited by launcher code before it can call `close_range`. Therefore integration is blocked until an explicit, reviewed transport design establishes how the launcher receives only required sources (e.g. a dedicated controlled descriptor channel established before launch), and how every unrelated descriptor is made inaccessible before untrusted target code; neither “inherit everything then clean up” nor CLOEXEC alone meets that requirement. Do not claim the current parent contract is achieved merely by trusting the launcher.

The design needs the target executable fd and stdio/error sources, with collision-free identities and a specified transport. The exact launcher image itself must be authenticated independently of the target image through a trusted immutable binding (for example, its own verified sealed executable binding and digest supplied by a separately trusted authority). A target digest does not authenticate the launcher, and a trusted launcher image does not itself establish that the parent used the required transport, withheld ambient descriptors, or launched that exact image. Those are separate mechanism and verification obligations. Reject scripts; accepted executable images are static ELF only.

## Exact child algorithm

This sequence is conditional on the unresolved transport/pre-launch controls above. It cannot recover source descriptors already closed by launcher exec or prevent non-CLOEXEC ambient descriptors being present before cleanup.

Reserve the error-pipe writer at a known fd >=4 before mapping, but distinguish its ownership: the parent retains the read end only; it must close every writer copy after launch setup, and the launcher must close inherited/temporary duplicate writer copies except its single reporting fd. Otherwise EOF is not observable when expected and any holder can forge or suppress a record. Do not duplicate the reserved writer into an untracked alias. Call `close_range(0, UINT_MAX, CLOSE_RANGE_UNSHARE|CLOSE_RANGE_CLOEXEC)` to unshare and mark descriptors CLOEXEC. The man page describes `CLOSE_RANGE_UNSHARE` as unsharing before closing/marking; it does not promise the combined operation is an atomic transaction/snapshot against concurrent descriptor-table changes. Establish and document quiescence of other actors that can alter the child table through the transition, or verify the precise deployed kernel semantics and residual race boundary before relying on it. Even after unsharing, duplicated descriptors reference shared open-file descriptions; descriptor-table isolation does not isolate file offsets, status flags, sockets, or peer effects. Any syscall error aborts. This marks rather than immediately closes descriptors: they remain accessible to launcher code until exec; launcher code must not inspect or act on unselected descriptors.

After descriptor-table quiescence is established, duplicate each selected stdio and executable source to distinct temporary descriptors above 3 with `F_DUPFD_CLOEXEC`, excluding the single reserved error writer and existing temporaries. Complete all source duplicates before modifying 0/1/2/3, then use checked `dup3(temp,target,0)` to map stdio to 0/1/2 and executable to 3; flags 0 clear CLOEXEC on each mapped target, so explicitly set `FD_CLOEXEC` on fd 3 with `fcntl(F_SETFD, FD_CLOEXEC)` after mapping. Keep the one error-writer fd separate and CLOEXEC. Check `F_GETFD` flags on fd 3 (CLOEXEC set), 0/1/2 (CLOEXEC clear), and error writer (CLOEXEC set), as well as target identities. Close temporary copies and check errors. `dup3`/`fcntl` success does not validate semantic suitability of any source. Handle fd 3/source collisions by this all-sources-first rule; reject mappings that cannot be represented without losing source identity.

Verify fd 3 is the intended sealed memfd: `fstat` identity matches the bound object; `F_GET_SEALS` includes `F_SEAL_WRITE|F_SEAL_GROW|F_SEAL_SHRINK|F_SEAL_SEAL`; recompute SHA-256 from that exact fd and compare to authenticated digest; validate static amd64 ELF from that same fd. Binding-time checks alone are insufficient if descriptor substitution is possible. Execute via `execveat(3, "", argv, envp, AT_EMPTY_PATH)`. Successful static ELF exec closes fd 3 due to CLOEXEC, leaving only 0/1/2 among descriptors intentionally carried through this launch. The oracle tests descriptor inheritance under its explicitly controlled test conditions; `execve(2)` notes that a privilege-gaining exec may open closed standard descriptors to unspecified files, so do not generalize to that case. Any returned syscall is failure.

The documented `UNSHARE` behavior should not be described as an atomic snapshot: the man page says unshare before close/mark, avoiding races with other threads sharing the fd table. This proposal still requires proving that this exact operation is sufficient for its transition, and controlling concurrent descriptor-table mutation until unsharing is effective. CLOEXEC marking is not immediate closure; descriptors remain accessible in the launcher until exec. Duplicated fds can still refer to shared open-file descriptions and shared underlying resources. A hostile process controlling launcher memory is outside this boundary.

## Error channel, signals, ambiguity

The reporter writer is held only by the launcher after setup: parent closes its writer copy, and every other duplicate is closed before waiting for EOF. A complete, validated fixed-size stage+errno record reports setup/exec failure; parent must reject truncated/partial records as indeterminate or malformed, never parse them as success. EOF with no bytes can follow CLOEXEC successful exec, but also writer closure, pre-report death, failed/partial write, or other loss; EOF is never proof of success. EOF is meaningful only after the parent has closed its writer and all known writer duplicates; unknown writer holders can prevent EOF indefinitely. Correlate complete records, EOF, and child wait status; optional post-exec handshake proves startup only. There is no guarantee an EINTR-retried write is bounded or completes: signals may recur and a syscall/kernel can stall. Signal policy and bounded record size reduce expected work but do not create a wall-clock guarantee. Parent pipe reads, child exit/reaping, startup, and syscalls may stall, including uninterruptible sleep; classify timeout or unobservable completion as indeterminate.

## Synthetic test oracle

A static helper enumerates `/proc/self/fd` after exec and reports descriptors over a designated standard stream. The oracle itself opens a directory fd; identify/exclude only that fd by identity. Assert selected descriptor inheritance, fd 3 CLOEXEC closure, and absence of injected sentinels under the specified test execution conditions. Do not assert standard descriptors are always preserved across exec: `execve(2)` documents that when a privilege gain would occur, closed fds 0/1/2 may be opened to unspecified files. Keep all tests non-privilege-changing and explicitly provision all three stdio descriptors if asserting their identities. Test helper must not open unrelated descriptors before enumeration. Verify stdio identity/type; cover sentinels (files, sockets, pipes; CLOEXEC and non-CLOEXEC at varied numbers), crossed mappings, source/target collisions, duplicate sources, fd pressure, and cleanup. Fault injection of mapping, `close_range`, and `execveat` failures must fail closed and reap child; simulate complete, partial, and no-record error-channel outcomes and require non-success/indeterminate classification. These tests are behavioral, not proof against kernel/runtime defects.

## Limitations and gate

The documented `UNSHARE` semantics protect against shared-table races only once the unshare transition is effective; do not characterize the combined flags as an atomic descriptor snapshot. Quiescence/control of concurrent table modifiers, exact launcher image authentication, and an explicit source transport remain integration blockers. Static ELF and fd policy do not prevent malicious executable behavior. Kernel semantics, launcher correctness, and trusted inputs remain assumptions. Resolve environment-policy mismatch and these blockers before separately proposing implementation; no behavior here is implemented.
