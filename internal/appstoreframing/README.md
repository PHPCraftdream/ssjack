# Application-store ciphertext framing

`Inspect` consumes exactly one proposed-v1 snapshot through an `io.Reader`: the 220-byte public header, its ordered data records, the final record and EOF. It uses `appstoreheader` admission before body processing. Each data prefix must have the exact sequential index, expected full/residual plaintext size and ciphertext size `plaintext+16000`. Final framing is exactly `FIN1`, big-endian uint64 length 16048, and that many bytes. No trailing bytes are accepted.

The returned copy-safe `Info` contains only the public Header, a SHA-256 transcript and a framing-admission flag. The transcript covers every complete encoded data record, including each 12-byte prefix and ciphertext body, in order. It excludes the public header and the entire final record as required by `docs/application-store/WIRE.md`. No record body is retained or exposed. The zero Info is invalid; every error returns it without partial metadata.

Body reads use one 32768-byte buffer, cleared best-effort at return. Every read request is at most that size; allocation does not scale with declared payload or chunk count. Validated header caps bound indices, subtraction, length conversion and the total expected byte count. Parsing is linear in actual bytes consumed. It does not impose a hard wall-clock deadline or cancel an arbitrary blocked Reader: the caller must provide a finite source or a Reader with independently enforced cancellation/deadlines. Sources must obey the `io.Reader` contract. Zero-progress reads fail closed rather than spin.

`ErrInvalid` means received framing is inconsistent, truncated or has trailing bytes. `ErrUnavailable` covers nil/no-progress readers and non-EOF I/O errors, including an error reported alongside a complete read. Raw I/O error messages are not returned. Neither error proves that a file on disk is corrupt or authorizes deletion, rollback, replay or repair.

This is NOT authentication or encrypted-store readiness. Ciphertext-shaped zero or modified bodies can pass framing; only their unkeyed transcript is computed. No KDF, AES/GCM tag, final plaintext/transcript, catalog, object, anchored state, nonce reservation, freshness, policy or SecretRef is verified here. Lengths account for the proposed 1000 tags but do not prove those layers were generated. A future caller must authenticate the full snapshot, immutable source and anchor/context before releasing any bytes or metadata to a consumer/model. Four independent sequential 1-GiB Argon2id derivations, 1000 AES-256-GCM data/final layers and all SSH formats remain unchanged and separate. No files, paths, network clients, writers, credentials or MCP tools are selected or created by this package.

Independent synthetic fixtures and standard-library transcript expectations cover full/residual chunks, all prefixes, truncation/trailing bytes, short reads, read bounds, operational errors at exact boundaries, maximum headers without payload-sized allocation and copy ownership. Tests explicitly demonstrate that framing admission is not AEAD authentication. Tests were authored but not executed locally; public GitHub CI supplies execution evidence. Local work ran formatting only.
