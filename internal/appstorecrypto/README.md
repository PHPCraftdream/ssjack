# Dedicated application-store master derivation

`Derive` implements only the dedicated master prerequisite from `docs/application-store/CRYPTO.md`. It is NOT an unlock-success test, authenticated snapshot, encryption service or authority token. Any structurally valid passphrase derives a key; correctness requires later full snapshot AEAD/anchor/context verification. No TTY, file, network, randomness, store creation, public record Seal/Open, secret-byte release or MCP path is implemented here. The private 1000-layer opening primitive is used only by the read-only metadata checker below; sealing has no production caller and no nonce/release gate is bypassed.

Input is a framing-admitted Header and 1..16384 exact bytes of strict UTF-8 scalar text without NUL. No trimming or Unicode normalization occurs. An internal byte API cannot establish human presence: a future human-controlled echo-disabled TTY must strip only its submitted LF/CRLF terminator before calling, never use model prompts, argv, environment or files. Direct API newlines remain meaningful bytes rather than silently stripped input.

The production function executes four independent sequential Argon2id-v1.3 derivations over the same owned passphrase copy and the header's four validated salts: m=1048576 KiB, t=1, p=1, output=32 bytes each. A shared `kdfgate` lease covers all four rounds and HKDF, coordinating with existing SSH unlocks. `M=HKDF-SHA256(A0||A1||A2||A3, absent salt, ASCII("ssjack-appstore/v1/master"), 32)`. No production profile, domain or lower-cost switch is caller-selectable. SSH master/domain/container interpretation is unchanged and never shared.

Caller password bytes are not modified. Owned password, intermediate outputs/concatenation and transient key are cleared best-effort; only the owned 32-byte M is retained. A private shared state pointer means copied Master handles observe the same `Close`; it clears that owned key and invalidates all handles, idempotently and under a mutex. Nil and zero handles are closed. No raw-key getter exists. `Matches` checks only the original store/salt context; fresh snapshot/nonce fields do not rederive a master. This is not snapshot authentication, nonce confirmation, consumer authorization or proof of a correct passphrase.

Observed cancellation while waiting, between rounds or before publication returns no Master. An active Argon2id invocation is not interruptible; its lease is retained until that invocation returns and cleanup runs. No hard wall-clock, host-wide RSS limit, guaranteed erasure of runtime copies/Argon workspaces, swap/dumps protection or resistance to OS/same-UID/root compromise is claimed. The fixed public-operation budget below does not replace full transaction lifetime/lock management. Trusted input, authenticated nonce reservation, snapshot assembly, source pinning, trusted expectations and two-pass release policy remain mandatory higher-level work.

Unit tests use only a private injected fake derivation seam, independently compute RFC5869 through HMAC, and check exact order/bytes/domain, clearing, shared admission, cancellation, bounds and copied-handle lifecycle. The production-profile test is gated by `SSJACK_TEST_FULL_KDF=1` in the existing GitHub CI job and compares the public Derive output to an independent fixed 1-GiB Argon2id/HMAC oracle, serially. Ordinary test jobs skip that full-cost test. Tests were authored but not run locally; only formatting was run. No real passphrase or credential was obtained.

## Private layered records

Unexported `sealRecord`/`openRecord` implement the proposed recurrence: each of exactly 1000 AES-256-GCM seals encrypts the entire previous ciphertext, adding 16 bytes; reverse opening verifies every tag. There is no caller-selectable layer count or public encryption/decryption API. A plaintext record of size n produces exactly n+16000 bytes. Data index and full/residual length must match the Header. Final uses index 0xffffffff, plaintext 48/ciphertext 16048, with FIN1/total/count fields validated before sealing and after opening. The final transcript hash itself still requires whole-snapshot comparison elsewhere.

Per-layer keys, HMAC-derived 12-byte nonces and AAD follow CRYPTO.md exactly, including distinct data/final domains, store/snapshot/index/layer identities, the full 220 header bytes, base plaintext/full ciphertext lengths and purpose label. Transient derived key bytes are cleared best-effort, but AES/HKDF/runtime internal copies are not guaranteed erased. Working buffers are owned; caller input is unchanged, errors return no partial bytes and clear the owned capacity, and discarded opening tails are cleared. A private layer-index observer is used only by tests; it exposes no key or buffer.

A try-lock protects the owned master during a record, returning Busy rather than queueing another record. Close waits for that owned-key use; observed cancellation stops between layers and before return. This mutex is not a global per-store lock across separately derived masters or the two-operation process budget. Cancelling encryption after reservation must still consume that reservation; retaining M is not permission to reuse a header/nonce. These private primitives must not be exposed until the full authenticated reservation, durability and release protocol is enforced. Individual record plaintext is not a verified snapshot or trusted consumer handoff.

Synthetic test masters avoid expensive Argon in ordinary jobs, but record tests perform the real fixed 1000 AES layers. Independent HMAC/HKDF/AES oracles cover a full 1-MiB data chunk, residual and final records; a corrupted inner tag is rewrapped in valid outer layers to prove all tags are checked. Tests also cover header/index/domain binding, authentic malformed final framing, busy/closed/scope/size/cancellation/input ownership and cleared tails. They were authored but not run locally; public GitHub CI supplies execution evidence. No production crypto approval or independent audit is implied.

## Phase-one metadata check

`CheckSnapshot` accepts a Reader and an explicit nonzero expected `(store_id,snapshot_id,encoded_file_hash)`. It verifies the received exact header/scope, sequential record framing and lengths, all 1000 tags of every data/final record, final FIN1/total/count/transcript, exact EOF, full encoded SHA-256 and canonical catalog/object spans. It returns only private copy-safe Header/Catalog/hash metadata after all checks. No object-byte accessor, callback or consumer sink exists. Errors return a zero SnapshotCheck, with opaque read errors and no partial metadata.

The checker retains only the decrypted catalog and fixed per-record buffers. Other chunk plaintext and final buffers are cleared immediately; owned working buffers are cleared on return best-effort. No allocation scales with total claimed snapshot size; read requests are at most 32768 bytes. Key ownership remains per record; interleaved operations/Close may cause Busy/Closed failure rather than publish partial metadata. The Reader can block and must have caller-enforced deadlines/cancellation. The public entrypoint uses the fixed process/store admission budget below, but no filesystem/cross-process lock or source identity/immutability is established.

`SnapshotCheck.Valid` is conditional verification of the bytes received against the supplied tuple and derived key, not proof that the tuple is human-enrolled, authenticated-current or authorized-historical. A caller can manufacture its own expectation. Historical expectations need independently trusted capture, not current-anchor substitution. The result does not pin a file or prove that a later Reader yields the same bytes. The required second-pass pinned source identity/hash checks, per-object policy/consumer/sink authorization, retention/revocation and partial-delivery handling remain outside; no plaintext may be delivered on this result alone. No nonce reservation, writer, durability, service, TTY, MCP or public Seal/Open is implemented.

Tests compose real 1000-layer synthetic snapshots and independently hash their wire bytes. Authentically tagged/pinned wrong-transcript and invalid-span catalogs must fail, as must wrong passphrase/hash/scope, tampering, truncation/trailing, cancellation and operational I/O error. Metadata ownership/read bounds and cleanup are checked. The existing full-cost master test is moved unchanged into the master test file to retain the seven-entry directory cap; no profile coverage was removed. Local work remains formatting only; execution evidence is public CI.

## Public primitive admission

Public `Derive` and `CheckSnapshot` own `appstorebudget` admission around the complete call: at most two active application-store operations in this process, with at most one for a given store ID, returning Busy without queueing when occupied. Derive uses the header store; CheckSnapshot uses the explicit expected store before reading or decrypting. The independent shared KDF gate still limits SSH/app password derivation to one batch. Private test/layer helpers are not additional public operation APIs.

Cancellation does not revoke a still-running operation or free its budget; release occurs only at actual return. The budget is cooperative/process-local, not a host-wide cap, cross-process filesystem lock, authenticated store identity, fairness guarantee or complete writer transaction. Future composite controllers must enforce the entire transaction/lock lifetime without nesting a second lease around these already-admitted entrypoints. No credentials or payloads are stored in the two fixed admission slots. Tests cover denial before fake KDF and Reader work, real-profile public-call release, cancellation and error paths.
