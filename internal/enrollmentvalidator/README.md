# Isolated enrollment validator

This package checks the proposed enrollment record without connecting it to execution, authentication, authorization, or live OS state. `Validate` accepts noncanonical JSON, rejects duplicate decoded keys, checks the incoming artifact and dependency map keys are strictly sorted by decoded key before using canonical output, and returns the domain-separated digest of the canonical record. Because the documented raw-order interpretation is ambiguous, this is a conservative fail-closed restriction; whitespace and unrelated object key ordering need not be canonical. For signed distribution, first call `enrollmentauth.VerifyCanonicalBytes` on the envelope with an independently trusted root, then `Validate` the returned manifest and compare digests. The signed profile requires exact canonical manifest bytes; `Validate` alone does not enforce that profile. Neither step establishes trust, operator approval, rollback protection, or runtime policy enforcement.

The validator deliberately rejects external schema documents outside `externalschemasubset`, which is not full external-dialect conformance. It restricts artifact and dependency map keys to the Name grammar, although the enrollment document does not specify that grammar for map keys. It rejects empty working-directory device and file_id and empty Windows SID, although the documented string shapes allow empty strings. Working directory paths are restricted to slash-rooted or drive-absolute forms; other absolute path forms are rejected.

Canonical JSON limits apply to the entire enrollment: input at most 262144 bytes, canonical output at most 65536 bytes, depth at most 16, nodes at most 4096, arrays at most 256 entries, and objects at most 128 properties. These global bounds can reject otherwise documented combinations. The signed-envelope verifier has a separate 131072-byte envelope input limit.

The validator cannot establish that a path is private, an artifact or dependency is immutable, a principal or OS identity is authentic, or a network policy is actually enforced. Those checks require independent trusted mechanisms.
