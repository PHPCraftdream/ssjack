# Application-store anchor-state encoding

This isolated package implements structural admission and hashing for the proposed 192-byte state in `docs/application-store/IO.md`. It is not an anchor, service, transport, signed reply, journal verifier, authoritative state or permission to encrypt. Production MCP and SSH interfaces are unchanged.

`Parse` requires exact `SSAS`/version-1 framing, all reserved bytes zero and a matching nonzero expected store ID. Sequence and journal count are unsigned big-endian uint64 values; count is at most 2^20 and sequence cannot exceed count because each commit consumes a reservation. Sequence zero requires the entire committed snapshot/hash/transaction tuple to be zero; positive sequence requires all three fields nonzero. Uncommitted states with positive reservation count are admitted.

Journal head must be nonzero. At count zero it must equal `SHA256(ASCII("SSAPP-JOURNAL-GENESIS-v1") || store_id)`. A positive count must not retain that empty-journal head; a hash-chain collision is an integrity failure, not a usable reservation. Other non-genesis heads are only structurally admitted: the complete anchored prefix must still be checked against the exact count and hash chain. State hash is exactly `SHA256(ASCII("SSAPP-ANCHOR-STATE-v1") || state_bytes)`. Neither domain includes an added NUL. These are app-store binary domains, not the declarative canonical-JSON registry.

`Genesis` constructs those canonical initial bytes only. It does not enroll, contact CreateIfAbsent, reset an existing store or prove absence. `State` keeps copied private bytes and returns arrays by value. Its zero value is invalid; every error returns it with `ErrInvalid` and no partial metadata. `Valid` means encoding admission, not authentication or freshness.

A caller must independently establish human-enrolled service/credential identity, authenticated anti-replay transport, signed correlation-correct replies, actual linearizability/durability, journal prefix/uniqueness, transition validity and rollback/fencing requirements. This parser has no prior trusted sequence with which to detect rollback. An authorized malicious writer or compromised service is not made safe by matching an unkeyed hash. There are no I/O, network, credentials, signing, CAS, KDF, encryption, snapshot-byte release, retry or recovery operations here. No nonce reservation is confirmed by this value.

Independent wire/hash vectors, every reserved byte, full committed-tuple combinations, scope/genesis binding, uint64/counter boundaries and copy ownership are covered by authored tests. Tests were not executed locally; only formatting was run. Public GitHub CI supplies execution evidence. The four sequential independent 1-GiB Argon2id derivations and 1000 AES-256-GCM layers remain separate unchanged requirements.
