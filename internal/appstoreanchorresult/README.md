# Causal anchor reply metadata

This pure checker composes `appstoreanchorrequest` and signature-checked `appstoreanchorreply` metadata. It performs no I/O, sending, mutation, journal update, crypto derivation, nonce grant, replay or recovery. Supplied signature validity still does not establish human enrollment, trusted key provenance, authenticated TLS/credential session, freshness, service durability or linearizability.

`CheckMutation` requires exact original operation, store and request IDs. A Committed reply must contain the exact immutable proposed State, not merely a valid signature/state hash or a matching transaction name. Otherwise it returns zero and `ErrInvalid`. `ExactRecordedResult` describes a signed recorded operation result, not the latest current state or production commit authority. Conflict/Unknown return `ReadRequired`; Rejected returns `ReportedRejected`. None is an instruction to send or retry anything.

`ClassifyRead` requires a separate Read request for the same store and a reply correlated to that exact Read. It reports `AtProposed` only for exact proposed State equality, `AtExpected` only when a CAS expectation hash matches the admitted observed State, and otherwise `AtOther`. Create has no CAS predecessor; a matching genesis describes that the desired initial state exists, not proof that this particular Create request executed. `ReportedMissing` applies only to the received metadata and never authorizes recreating an enrolled store or retrying a CAS. Unknown and Rejected reads remain unavailable/rejected, not state assertions.

Service versions are deliberately not treated as a global freshness counter here: a recorded idempotent mutation reply may precede a later current-state Read. A later Read must not rewrite the original immutable request/key/result. The caller must independently authenticate actual requests/replies, enforce current trusted version/history and durable idempotency semantics, and compare retained original intent/candidate/prefix context before any action. Matching a tuple alone does not prove source identity, byte durability, authorization, nonce uniqueness or permission to encrypt/release.

All errors return zero classifications without partial success or raw backend text. No function rebuilds a replacement CAS, chooses a current snapshot, changes request bytes, infers reparenting, or performs automatic replay. The production declarative surface, SSH formats, four independent 1-GiB Argon2id derivations and 1000 AES layers are unchanged.

Synthetic signed fixtures isolate exact/wrong results and each operation/store/request correlation field with valid signatures. Tests cover expected/proposed/other, creation/not-found, unknown/conflict/rejected, recorded-vs-current results and unchanged original bytes. Tests were authored but not run locally; public GitHub CI supplies execution evidence. Local work ran formatting only.
