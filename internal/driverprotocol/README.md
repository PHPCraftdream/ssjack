# Driver protocol structural checks and pinned schemas

`internal/driverprotocol` provides structural request/response checks, frame I/O, and opt-in validation against caller-supplied pinned schemas. Structural success alone does not establish enrolled/runtime schema conformity, semantic validity, authorization, safe execution, or policy acceptability. This package is not integrated with driver execution; callers supply identities/documents and remain responsible for enrollment resolution and authorization.

Parsing rejects non-ASCII strings, duplicate keys, invalid UTF-8, floats, unsafe integers, excess depth/nodes/container sizes, extra JSON values, and extra bytes after a frame. Go's decoder replaces lone surrogate escapes with U+FFFD, which is rejected as non-ASCII; valid surrogate pairs are also rejected. Frame writing checks bounded generic JSON only; it does not validate request/response shapes. Frame readers require EOF, so writers must be closed and deadlines enforced by callers.

Pinned schema validation uses a strict subset of the Draft 2020-12 dialect: root `$schema` must be `https://json-schema.org/draft/2020-12/schema`; supported keywords are `type`, `enum`, `const`, and type-applicable `properties`, `required`, `additionalProperties`, `items`, `minItems`, `maxItems`, `minLength`, `maxLength`, `minimum`, and `maximum`. All other keywords reject, including `$schema` below root. Objects are closed and all listed properties are required. Arrays require `items` and bounded `maxItems`; strings require bounded `maxLength`; only safe integer bounds are supported. Strings and keys are printable ASCII, so Unicode scalar counting and NFC normalization are not implemented. Unsupported features include nullable type arrays, references, patterns, formats, exclusive bounds, `multipleOf`, `uniqueItems`, tuples, metadata keywords, and arbitrary additional properties. This is not full JSON Schema or v1 protocol conformance.

Input/depth/node bounds come from `ParseJSON` and explicit schema limits; schema input and canonical representation are bounded to 65536 bytes. Desired/projection size accounting uses locally sorted compact integer JSON; Go JSON string marshaling HTML-escapes `<`, `>`, and `&`, so estimates may exceed JCS lengths. To prevent HTML escaping from changing pinned schema digests, schema strings and object keys containing any of `<`, `>`, or `&` are rejected. This serialization is neither a JCS implementation nor a general canonicalization claim. No schema lookup, runtime execution, authorization, or MCP integration is performed.

`ValidatePinnedValue` accepts raw pinned schema bytes, expected schema ID/digest, actual target/kind/schema ID, and raw value bytes. It parses both with `ParseJSON`, applies structural bounds, computes the `ssjack-schema-v1\0` digest, and only then validates the value. `ValidatePinnedProjection` checks the request schema ID against the correlated structural request and separately pins the projection document/digest; desired and projection IDs may differ as specified by Kind enrollment. `ValidatePinnedRequest` accepts only plan/apply; use structural validation for other actions, which does not claim schema validity. Callers provide the enrolled identity/document; these helpers do not resolve enrollment or authorize it. This deliberately partial subset is not v1 conformance or full Draft 2020-12. Exclusive bounds, `multipleOf`, `uniqueItems`, nullable type arrays, references, patterns, formats, metadata keywords, and Unicode scalar/NFC canonicalization are unsupported. No automatic schema lookup, execution, authorization, or MCP integration is performed.
