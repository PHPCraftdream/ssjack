# Driver protocol structural checks

`internal/driverprotocol` provides structural request/response checks and frame I/O only. The `Structural` names are intentional: success does not establish that a message conforms to an enrolled/runtime schema, is semantically valid, authorized, safe to execute, or acceptable under policy. No runtime path invokes this package; it is not integrated with driver execution.

Checks reject non-ASCII strings, duplicate keys, invalid UTF-8, floats, unsafe integers, excess depth/nodes/container sizes, extra JSON values, and extra bytes after a frame. Go's JSON decoder replaces lone UTF-16 surrogate escapes with U+FFFD; the resulting non-ASCII string is rejected. A valid surrogate pair likewise decodes to non-ASCII and is rejected. `WriteStructuralFrame` checks only generic bounded JSON syntax; it does not validate a request or response. These checks do not establish full v1 protocol conformance: they do not validate against enrolled JSON schemas, enforce stdout/process exit/deadlines, or implement driver execution. This package is not runtime-integrated. Desired and projection byte bounds use a locally sorted, whitespace-free integer JSON serialization. This is a conservative size estimate: Go string marshaling HTML-escapes `<`, `>`, and `&`, potentially counting more bytes than JCS; this package neither asserts canonical input nor computes digests. Frame readers require EOF; callers must close writers and enforce deadlines.
