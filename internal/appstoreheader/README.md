# Application-store public header admission

This isolated package parses only the exact 220-byte public header proposed in `docs/application-store/WIRE.md` and `CRYPTO.md`. It does not read or write files, derive keys, encrypt/decrypt, obtain passphrases, generate randomness, reserve nonces, parse catalogs or records, or resolve SecretRefs. SSH formats, keyfile limits and crypto domains are unchanged. The application store is not implemented or approved for production by this parser.

`Parse` takes exactly one header, copies its fixed bytes before inspecting them, and returns a copy-safe `Header` or a zero value and `ErrInvalid`. Private fields cannot be changed through accessors; byte arrays and salts are returned by value. The zero Header has `Valid()==false` and zero size metadata. `Valid` means public framing admission only, never authentication or authorization. Accessors expose public IDs, salts and nonce bytes, not secrets.

Admission requires ASCII magic `SSAPP001`, version 1, zero flags/reserved, chunk size 1,048,576, total plaintext 1,048,576..1,099,511,627,776, and the exact ceiling-divided chunk count within 1..1,048,576. Store and snapshot IDs, all four 32-byte salts and the 12-byte nonce base must be nonzero; salts must be pairwise distinct. Parent ID may be zero as a claimed genesis marker or nonzero. The parser cannot establish whether genesis, parent identity, salt continuity or snapshot freshness is authoritative; those require authenticated state and the complete format/anchor protocol.

`EncodedSize` accounts for the 220-byte header, every 12-byte data-record prefix, all plaintext, 16,000 tag bytes per data record, and the final 12-byte prefix plus 16,048 ciphertext bytes. Size arithmetic occurs only after all plaintext/count caps pass, keeping every intermediate below 2^41. No allocation or loop scales with a claimed snapshot length or chunk count. The returned length is an expected framing length, not proof that records exist or are valid.

Every actual data and final record still requires the proposed 1,000 sequential AES-256-GCM layers; the four sequential independent 1-GiB Argon2id derivations, dedicated master lifecycle, global operation limits and nonce-reservation rules remain separate unimplemented requirements. Public header admission proves no AEAD tags, final transcript, catalog partition, object bytes, nonce uniqueness, durability, rollback resistance, human provenance or consumer policy. No bytes may be released on the strength of this parser.

Tests include an independent literal header, exact hard-coded encoded-size expectations including the 1-TiB boundary, field and overflow rejections, all six duplicate-salt pairs, nonzero-field boundaries and mutation/aliasing witnesses. They were authored but not executed locally; only formatting was run. Public GitHub CI supplies execution evidence.
