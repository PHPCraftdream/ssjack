# License compliance review

`license_sha256`/`sha256` records normalized notice-text hashes (newline normalization and trimming) and is enforced against source text; `source_sha256` records exact upstream byte hashes. Source files are read as bytes and decoded as UTF-8 before hashing, preserving the source bytes for these UTF-8 files. GitHub Contents API JSON/base64 was decoded before hash calculation; API blob IDs are not content hashes. `factual_source_review: verified` records byte-level source matching, not a legal conclusion. Independent comparison of decoded pinned GitHub Contents API payloads with existing fenced notice blocks confirmed normalized text matches for the four module licenses and Go LICENSE/PATENTS text. Go extended-library LICENSE/PATENTS payloads match the Go release payloads. Source provenance is not legal approval.

The project-owned material is offered under the stated alternative expression `MIT OR Apache-2.0`; recipients may select either license. Third-party components retain their own license terms and may have dual, multiple, or additional grants (including the Go patent grant), which are not replaced by the project's license choice. Human legal review must assess those component-specific terms, attribution, redistribution, and grant applicability; no legal conclusion is made here. CI's license job verifies consistency only and does not assert legal approval. Human review of license terms, redistribution obligations, patent grant scope, and applicability remains required before release; automation is not legal advice or a compliance guarantee.

CI collects the actual Go dependency graph and first-party embed inventory for all six release GOOS/GOARCH targets, then compares those results with the exact explicit policy. This source graph has not yet been observed in CI for this change; target-graph accuracy remains unverified until that job runs. Missing, extra, unpinned, unreviewed, changed, or unknown licenses, absent Go toolchain LICENSE/PATENTS, and stale notice text fail closed. Do not set source-review status without obtaining and comparing exact pinned source bytes. Do not change legal review status to approved without actual human signoff.

CI reads each pinned `golang.org/x/crypto`, `golang.org/x/sys`, and `golang.org/x/term` module's own `PATENTS` file and verifies exact source and normalized notice hashes against policy; missing or changed files fail closed. CI checks module versions for divergence within each target while collecting `go list` results, before recording the module, and across target inventories. Source graph coverage remains unverified until CI runs on all six targets; these checks establish factual byte consistency only, not legal review.

The Go `EmbedFiles` inventory is collected only for first-party packages across CLI and UI plugin targets; module dependency embeds are excluded because dependency licenses are tracked by module policy. Paths are normalized relative to repository root. Explicit embedded policy includes project license files and plugin assets; `THIRD_PARTY_NOTICES.md` is dynamic and is checked against active module/toolchain license and PATENTS texts rather than self-digested. Project embed hashes were derived from local files, not legal review.

On dependency/toolchain updates, pin versions, inspect exact upstream terms, verify hashes, and refresh source attribution and notice text. Review copyright, attribution, patent, and redistribution conditions with a human before distribution.
