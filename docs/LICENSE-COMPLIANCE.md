# License compliance review

`license_sha256`/`sha256` records normalized notice-text hashes (newline normalization and trimming) and is enforced against source text; `source_sha256` records exact upstream byte hashes. Source files are read as bytes and decoded as UTF-8 before hashing, preserving the source bytes for these UTF-8 files. GitHub Contents API JSON/base64 was decoded before hash calculation; API blob IDs are not content hashes. `factual_source_review: verified` records byte-level source matching, not a legal conclusion. Independent comparison of decoded pinned GitHub Contents API payloads with existing fenced notice blocks confirmed normalized text matches for the four module licenses and Go LICENSE/PATENTS text. Go extended-library LICENSE/PATENTS payloads previously reviewed match the Go release payloads. For x/text v0.38.0, the cached module archive LICENSE and PATENTS match the recorded hashes; cached metadata identifies tag v0.38.0 and commit f4bb6328041b090f85b93014bd369edfcd24bdef. Pinned upstream LICENSE and PATENTS bytes and the sum.golang.org module checksum were independently compared: LICENSE SHA256 `911f8f5782931320f5b8d1160a76365b83aea6447ee6c04fa6d5591467db9dad`, PATENTS SHA256 `96f408bfae65bf137fc2525d3ecb030271c50c1e90799f87abf8846d8dd505cc`, and sum.golang.org module checksum `h1:sXmwo9DwP3OK9EZ7PqAdaooSGozfl/3a6/xJcbzPRhE=`. These match the recorded policy hashes and go.sum checksum. Source provenance is not legal approval.

The project-owned material is offered under the stated alternative expression `MIT OR Apache-2.0`; recipients may select either license. Third-party components retain their own license terms and may have dual, multiple, or additional grants (including the Go patent grant), which are not replaced by the project's license choice. Human legal review must assess those component-specific terms, attribution, redistribution, and grant applicability; no legal conclusion is made here. CI's license job verifies consistency only and does not assert legal approval. Human review of license terms, redistribution obligations, patent grant scope, and applicability remains required before release; automation is not legal advice or a compliance guarantee.

CI collects the actual Go dependency graph and first-party embed inventory for all six release GOOS/GOARCH targets, then compares those results with the exact explicit policy. `golang.org/x/text` is marked `release: false`: driver text validation uses it, but the audited CLI and UI plugin release roots do not currently import that path. CI downloads its pinned module separately and still verifies its LICENSE, PATENTS, and notice text; if it enters the release graph, the exact inventory check fails until the policy is updated. This distinction is inferred from the source and CI download log; target-graph accuracy remains unverified until the updated job runs. Missing, extra, unpinned, unreviewed, changed, or unknown licenses, absent Go toolchain LICENSE/PATENTS, and stale notice text fail closed. Do not set source-review status without obtaining and comparing exact pinned source bytes. Do not change legal review status to approved without actual human signoff.

CI reads each pinned `golang.org/x/crypto`, `golang.org/x/sys`, `golang.org/x/term`, and `golang.org/x/text` module's own `PATENTS` file and verifies exact source and normalized notice hashes against policy; missing or changed files fail closed. CI checks module versions for divergence within each target while collecting `go list` results, before recording the module, and across target inventories. Source graph coverage remains unverified until CI runs on all six targets; these checks establish factual byte consistency only, not legal review.

The Go `EmbedFiles` inventory is collected only for first-party packages across CLI and UI plugin targets; module dependency embeds are excluded because dependency licenses are tracked by module policy. Paths are normalized relative to repository root. Explicit embedded policy includes project license files and plugin assets; `THIRD_PARTY_NOTICES.md` is dynamic and is checked against active module/toolchain license and PATENTS texts rather than self-digested. Project embed hashes were derived from local files, not legal review.

On dependency/toolchain updates, pin versions, inspect exact upstream terms, verify hashes, and refresh source attribution and notice text. Review copyright, attribution, patent, and redistribution conditions with a human before distribution.
