# Declarative schemas, descriptor, and enrollment

**Proposed v1; not implemented or approved.** Normative proposed contract only.

## Canonical JSON Schema construction

Canonical JSON (`JCS-SSJACK-1`) follows the exact proposed string encoding and rejection rules in [policy.md](policy.md#canonical-values-and-binding): NFC Unicode scalar strings and keys; reject duplicate decoded keys, U+0000–U+001F, U+007F–U+009F, lone surrogates, floats and invalid JSON. Emit allowed scalars as literal UTF-8 except quote as `\"` and backslash as `\\`, including literal U+2028/U+2029. Sort object keys by Unicode scalar sequence; preserve array order; shortest decimal integers; no whitespace. Hash is lowercase SHA-256 of ASCII domain + NUL + canonical bytes. Domains: `ssjack-schema-v1`, `ssjack-tool-schema-v1`, `ssjack-enrollment-v1`, `ssjack-plan-v1`, `ssjack-desired-v1`, `ssjack-effects-v1`.

The following notation is a deterministic construction algorithm, not shorthand for an unspecified schema. Every emitted schema is a root object containing `"$schema":"https://json-schema.org/draft/2020-12/schema"` plus its defined schema keywords; `$schema` occurs only at that root and is never recursively emitted. `O{...}` emits `{"type":"object","properties":{...},"required":[...],"additionalProperties":false}`; properties and required names are sorted Unicode-scalar order. `S(n)` emits `{"type":"string","maxLength":n}`. `integer` emits `{"type":"integer","minimum":-9007199254740991,"maximum":9007199254740991}`; `integer[a..b]` uses those literal inclusive bounds instead. `bool` emits `{"type":"boolean"}`; `null` emits `{"type":"null"}`. `enum[v1,...]` emits `{"enum":[v1,...]}` in the stated order, with distinct JSON values. Nullable non-enum `T?` emits a type array including null and the constraints applicable to T; nullable enum emits a literal enum with null appended. For nullable object T, the type array is `{"type":["object","null"],...T object constraints}`, preserving `properties`, `required`, and `additionalProperties:false`.

`array<T>[m..n]` emits `{"type":"array","items":T,"minItems":m,"maxItems":n}`. `map<T>[m..n]` emits `{"type":"object","minProperties":m,"maxProperties":n,"additionalProperties":T}`; keys are strings, unique by JSON object semantics. Fixed objects are closed. Common schemas also use bounded dynamic nodes (including maps and the explicitly defined arbitrary-JSON value node below); these do not make fixed objects open. `Name` is `S(64)` plus validator grammar `[a-z][a-z0-9._-]{0,63}`; `ResourceId=S(128)` plus `[A-Za-z0-9][A-Za-z0-9._:-]{0,127}`; `Revision=S(128)` plus `[A-Za-z0-9._:-]{1,128}`; `Digest=S(64)` plus lowercase hex grammar; `Id=S(22)` plus exact unpadded base64url encoding of 16 bytes; `Time=S(24)` plus UTC RFC3339 millisecond grammar. Lexical constraints are validator rules because this dialect forbids `pattern`/`format`. Nullable object schemas use a type array, e.g. `{"type":["object","null"],"properties":{},"required":[],"additionalProperties":false}`; apply the common validator bounds to nested values and reject excessive depth/size regardless of schema.

`ExternalSchemaDocument` values used by `SchemaEntry.document` are data documents containing schemas to validate against, and are bounded by the external schema dialect: a JSON object schema with root `$schema` exactly as above, depth ≤16, ≤4096 nodes, canonical bytes ≤65536, only keywords `$schema,type,enum,const,title,description,default,examples,properties,required,additionalProperties,items,minItems,maxItems,uniqueItems,minProperties,maxProperties,minLength,maxLength,minimum,maximum,exclusiveMinimum,exclusiveMaximum,multipleOf`. Reject boolean schemas, unknown keywords/vocabularies, nested `$schema`, `$ref`, `$defs`, patterns, formats, composition/conditionals and non-integer numbers. `title`, `description`, `default`, and `examples` are allowed in external driver schema documents but are excluded from common hashed schemas and have no authority. Every object schema must set `additionalProperties:false` and require every declared property. Types limited to object,array,string,integer,boolean,null; type arrays only combine a non-null type and null. String maxLength 1..4096, array maxItems 0..256, object maxProperties 0..128; bounds nonnegative and within maxima; integers within safe range; multipleOf positive integer; enums 1..256 unique values. External schema documents are closed records in enrollment and digest-bound. Schema roots contain `$schema` and defined schema keywords only; no recursive metaschema. Common and legacy schema documents are also data documents containing schemas to validate against, but are not ExternalSchemaDocuments and MUST NOT be checked against the external closed dialect: common documents must match their deterministic constructed common schemas; full-mode legacy documents must match the unmodified legacy registry schemas. The exact common structural JSON Schema node for `CommonOrLegacySchemaDocument` data is `{"type":"object","maxProperties":128,"additionalProperties":true}`; its data values are bounded by common depth/node/byte limits. For nullable CommonOrLegacy schema fields, the schema-document type mapping admits null in addition to the document value (equivalently `{"type":["object","null"],"maxProperties":128,"additionalProperties":true}`), while non-null fields use the node as written. Structural validation of schema-document data is distinct from validation of the schema it contains.

## External dialect clarifications and open differences

The proposed external contract requires each explicitly typed string schema to contain `maxLength` (integer 1..4096), and each explicitly typed array schema to contain `maxItems` (integer 0..256), including nullable and nested schemas. These requirements do not apply merely because a typeless finite `enum` or `const` contains strings or arrays. The raw JSON input for an external schema document or a value checked against one is limited to 262144 bytes before canonicalization; the separate canonical output and context-specific value limits still apply. These are dialect and resource restrictions, not requirements of full JSON Schema.

For external annotations, `title` and `description` are strings, `default` is any bounded JSON value, and `examples` is an array of bounded JSON values. They do not affect matching. The opt-in pinned subset validates these shapes at root and nested nodes, including nullable nodes, under the existing whole-document JSON limits; it does not insert defaults or grant authority, and annotations remain part of the canonical schema digest. The isolated subset permits type-specific keywords on explicitly typed schemas of another type, validates their keyword values and nested schemas regardless, and applies them only to instances of the relevant type. Declared object and array schemas still require their respective closed and bounded shapes; mismatched object keywords do not admit object values under a different explicit type. For nullable types, `enum` and `const` also constrain null. Whether the full proposed external contract permits mismatched type-specific keywords remains unresolved; do not infer full contract conformance from subset acceptance or rejection.

The isolated implementation is not a full proposed v1 implementation or a general JSON Schema validator and remains disconnected from production validation and authorization. Other differences between it and the full proposed contract, including supported keyword coverage, remain to be resolved; the subset's fail-closed choices do not silently define the full contract.

The isolated pinned subset accepts `minProperties` and `maxProperties` only on explicitly typed closed, fully required objects (including nullable and nested objects). Each must be an integer from 0 through 128, and object matching counts actual properties inclusively. These constraints remain in the digest; a changed bound requires a new pin. The subset does not reject reversed or otherwise unsatisfiable property bounds at enrollment, and does not thereby support optional properties, omitted object shapes, or typeless schemas. Production validation and authorization remain disconnected.

For array schemas, `uniqueItems` is boolean. When true, no two elements may be equal JSON values: object key order and equivalent decoded string spellings do not distinguish values, while array order and JSON types do. False or omission does not reject duplicates. The isolated pinned subset enforces this at nested and nullable arrays alongside the other applicable constraints; it retains its existing rejection of mismatched keywords and reversed bounds, without resolving those contract differences.

For proposed v1 external array schemas, `items` may be omitted only when `maxItems` is explicitly the valid integer `0`; otherwise one nested `items` schema is required. A present `items` must always be a valid nested schema, even at zero. This applies to nullable and nested arrays; nonempty arrays cannot match `maxItems:0`. This clarification does not relax closed object validation.

For the proposed external dialect, an untyped schema that permits arbitrary objects without an explicit closed object shape is rejected, including an empty or annotation-only schema. A typeless `enum` and/or `const` is permitted as a finite-value constraint: it admits only the exact bounded JSON values enumerated (the intersection when both are present), including exact object contents, not arbitrary additional properties. An untyped explicit closed object shape is also permitted: it must set `additionalProperties:false`, require every declared property, and obey the object keyword bounds and nested schema rules. Object keywords apply only to objects, so non-object values are unaffected by them; any `enum` and `const` still apply to all values. In untyped schemas, other type-specific keywords are rejected, including in typeless finite constraints. These exceptions do not open object schemas; explicitly typed objects still require the closed shape above.

`SchemaValue` and `SafeProjection` are data JSON values, not schema documents, with max canonical encodings 32768 and 8192 bytes respectively. Their exact common JSON Schema node is `{"type":"object","maxProperties":128,"additionalProperties":true}`. This deliberately permits arbitrary nested JSON values at that node; validators still enforce strict JSON, NFC strings, safe integers, depth ≤16, ≤4096 nodes, arrays ≤256, object properties ≤128, and byte bounds. Separately validate desired/projection values against the exact enrolled desired/projection schema documents; those documents are closed and digest-bound. `SchemaEntry.document` is an `ExternalSchemaDocument`: its data value uses the same bounded common structural node, then is separately validated against the external schema-document dialect above. Structural node validation and schema-dialect validation are distinct; these are not recursive schema-dispatch or specialization rules.

## DTOs, tools, descriptor

`Driver=O{driver_id:Name,protocol:integer[1..1],kinds:array<Name>[0..128],capabilities:array<enum[observe,plan,apply,conditional_write,exclusive_owner,cancel,reconcile,verify_adoption]>[1..8],limits:Limits}`. `StatusIn=O{target:Name,driver_id:Name,kind:Name,schema_id:Name,resource_id:ResourceId}`. `StatusOut=O{state:enum[present,absent,unknown],revision:Revision?,observed_at:Time,projection:SafeProjection}`. `PlanIn=O{target:Name,driver_id:Name,kind:Name,schema_id:Name,resource_id:ResourceId,desired:SchemaValue,request_id:Id}`. `RuntimeEffect=O{class:Name,summary_id:Name,destructive:bool}`. `PlanOut=O{plan_id:Id,digest:Digest,expires_at:Time,effects:array<RuntimeEffect>[0..256],precondition:Revision?}`. `ApplyIn=O{plan_id:Id,request_id:Id}`; `ApplyOut=O{operation_id:Id,state:enum[RESERVED,RUNNING,SUCCEEDED,FAILED,CANCELLED,UNKNOWN]}`. `ReadIn=O{operation_id:Id}`. `Revisions=O{applied:Revision?,delivered:Revision?,observed:Revision?,adopted:Revision?}`. `SafeResult=O{verified:bool,projection:SafeProjection}`. `Error=O{code:S(64),message:S(256),retryable:bool,operation_id:Id?}`. `ReadOut=O{operation_id:Id,state:enum[RESERVED,RUNNING,SUCCEEDED,FAILED,CANCELLED,UNKNOWN],phase:enum[queued,observing,planning,applying,verifying,reconciling,cancelling,complete],progress:integer[0..100]?,revisions:Revisions,result:SafeResult?,error:Error?,updated_at:Time}`. `progress` is an integer percentage 0..100, or null when unsupported; it never proves completion or adoption. Missing revision evidence is null, never omitted or fabricated. No-op successful result uses actual fresh observation and its `observed` revision (or null only under exclusive ownership); `verified` indicates observed projection equals desired. `CancelIn=O{operation_id:Id,request_id:Id}`; `CancelOut=O{operation_id:Id,state:enum[RESERVED,RUNNING,SUCCEEDED,FAILED,CANCELLED,UNKNOWN],cancellation:enum[confirmed,unsupported,pending]}`. Cancellation is durable intent, not proof remote work stopped; cancellation retries resolve the durable intent and never cause duplicate driver invocations.

`PolicyEffect=O{class:Name,decision:enum[delegated,approval_required],destructive:bool,summary_id:Name}` is enrollment metadata, never a `RuntimeEffect`; `RuntimeEffect` is the existing runtime effect DTO above. Tools, in exact order: `driver_list O{} -> O{drivers:array<Driver>[0..128]}`; `resource_status StatusIn -> StatusOut`; `resource_plan PlanIn -> PlanOut`; `plan_apply ApplyIn -> ApplyOut`; `operation_read ReadIn -> ReadOut`; `operation_cancel CancelIn -> CancelOut`. `Tool=O{name:S(64),input_schema:CommonOrLegacySchemaDocument,output_schema:CommonOrLegacySchemaDocument?,schema_id:S(128),schema_digest:Digest}`; the schema fields contain schema-document data. The nullable `output_schema` mapping admits null as described above. The six declarative tool schemas are fixed common schemas, not specialized per enrollment; common documents must equal deterministic constructed schemas. Full-mode legacy fields must equal unmodified legacy registry schemas. Legacy output_schema is explicitly null where the current registry lacks an output schema; no fabricated legacy output schema is implied. Tool ID is `ssjack.tool.<name>.v1`; schema digest is SHA-256 of domain `ssjack-tool-schema-v1`, NUL, and canonical `{"input":<schema>,"output":<schema>}`; session ID is excluded.

`Descriptor=O{protocol:integer[1..1],min_protocol:integer[1..1],max_protocol:integer[1..1],min_request_bytes:integer[1..1],max_request_bytes:integer[262144..262144],mode:enum[full,declarative],session_id:Id,tools:array<Tool>[6..8]}`. Descriptor min/max protocol are both 1; the describe request also carries its negotiation range. Descriptor ID `ssjack.descriptor.<mode>.v1`. Declarative has exactly the six tools above. Full has exactly `remote_targets,remote_exec,remote_read,remote_cancel,app_list,app_exec,app_read,app_cancel`; output schemas are only legacy outputs, with nullable fields explicitly nullable and absent legacy fields remaining absent/null as in the legacy contract—do not fabricate outputs.

## Enrollment

Enrollment is one closed record, all fields required: `O{artifact_digests:map<Digest>[1..128],aliases:array<Alias>[0..256],capabilities:array<enum[observe,plan,apply,conditional_write,exclusive_owner,cancel,reconcile,verify_adoption]>[1..8],configuration_digest:Digest,dependency_digests:map<Digest>[0..128],driver_id:Name,driver_protocol:integer[1..1],effects:array<PolicyEffect>[1..256],enrollment_id:Id,environment:O{},executable:Executable,kinds:array<Kind>[1..128],limits:Limits,network:Network,os_identity:OSIdentity,principal:Principal,provenance:Provenance,resource_sinks:array<null>[0..0],schemas:array<SchemaEntry>[1..256],targets:array<Target>[1..128],working_directory:WorkingDirectory}`. Every nested `O` is closed. Capabilities are sorted, unique, known; `observe` mandatory. No capability implies authority beyond the matching target, effect, sink and principal policy.

`environment:O{}` (v1 child environment fixed empty, never inherited) and `resource_sinks:array<null>[0..0]` (no resource sinks in v1). `Executable=O{path:S(4096),sha256:Digest,interpreter:Interpreter,argv:array<S(4096)>[0..64]}`; `Interpreter=O{path:S(4096),sha256:Digest}`. `WorkingDirectory=O{path:S(4096),device:S(128),file_id:S(128)}` binds absolute private directory path and stable filesystem identity; verify before each invocation. `Dependency=O{name:Name,path:S(4096),sha256:Digest}`; `Provenance=O{source:S(1024),revision:S(256),dependencies:array<Dependency>[0..128]}`; dependency names/digests exactly equal `dependency_digests` map. Artifact and dependency map keys sorted; every digest binds named immutable artifact. `Principal=O{issuer:S(256),subject:S(256)}`. `OSIdentity` exactly one of POSIX `O{platform:enum[posix],uid:integer[0..4294967295],gid:integer[0..4294967295],groups:array<integer[0..4294967295]>[0..64]}` or Windows `O{platform:enum[windows],sid:S(184)}`; verify account identity independently before every process.

`Target=O{name:Name,canonical_target:ResourceId}`. `Kind=O{name:Name,desired_schema_id:Name,projection_schema_id:Name}`. `Alias=O{target:Name,kind:Name,resource_id:ResourceId,canonical_target:ResourceId,canonical_resource:ResourceId}`. Alias array sorted lexically by `(target,kind,resource_id)`, unique on that triple; targets/kinds sorted by name, unique. Every alias target and kind must be enrolled. Every accepted `(target,kind,resource_id)` must have exactly one alias mapping to `(canonical_target,canonical_resource)`; canonical target must equal the enrolled target's canonical target. Multiple accepted identities may map to the same canonical pair; never map one accepted identity to multiple pairs. Resolve before authorization/interlock; interlock only canonical pair, independent of alias/session/driver. Target+kind/resource scope is finite and exact; no wildcard/default mapping.

`Network=O{policy:enum[deny_all,allow_list],targets:array<NetworkTarget>[0..128],policy_digest:Digest}`. `NetworkTarget=O{protocol:enum[tcp],host:S(253),port:integer[1..65535]}`. Targets sorted by `(protocol,host,port)`, unique; host lowercase DNS labels only, no wildcard, IP literal or trailing dot. `deny_all` requires empty targets; `allow_list` requires at least one. `policy_digest` identifies the immutable, reviewed, actual OS/backend-enforced network policy; it is not a hash of the labels in this enrollment record. Network policy must be independently verified and changes require re-enrollment. `Limits=O{process_slots:integer[1..4],session_operations:integer[1..32],global_operations:integer[1..64],emergency_cancellations:integer[1..16],storage_bytes:integer[1..16777216],records:integer[1..256],cancellation_reserve_bytes:integer[4096..4096]}`; no total-active limit is defined. Ordinary process concurrency per enrollment is bounded by `limits.process_slots` (1..4), with at most one separate emergency cancellation process. Admission also obeys lifecycle global ordinary process cap 64 and emergency cancellation process cap 16; limits cannot exceed listed bounds.

`SchemaEntry=O{id:Name,digest:Digest,document:ExternalSchemaDocument}`. The `schemas` array is sorted ascending by `SchemaEntry.id` in Unicode-scalar lexical order; duplicate IDs are rejected. Every schema ID resolves to exactly one included document; digest equals SHA-256(domain `ssjack-schema-v1`, NUL, canonical document). Each Kind's desired/projection IDs resolve to matching documents. `PolicyEffect` arrays sorted by `(class,summary_id,decision,destructive)` and unique. Schema, target, kind, alias, network-target and map ordering rules above are mandatory; reject duplicates before canonicalization. `CommonOrLegacySchemaDocument` names the common schemas and existing legacy Tool schema fields; it is distinct from `ExternalSchemaDocument`, used only for `SchemaEntry.document`.

`approval_required` permits observe/plan, never executable apply. `conditional_write` is required for conditional mutation; `exclusive_owner` may support revision-less checks; `reconcile` and `verify_adoption` required for corresponding actions. Tombstones for durable operation identities persist and retries resolve them before expiry checks; never evict unresolved/unknown records. Enrollment digest hashes full canonical enrollment with `ssjack-enrollment-v1`; runtime session ID is excluded from the digest. Human review and authenticated distribution are independent; schema or policy change requires a new enrollment.

Limits outside enrollment: desired ≤32768 canonical bytes; projection ≤8192; driver frame ≤65536 payload; broker Ktav ≤262144. Four ordinary processes per enrollment plus separate cancellation slot; lifecycle global ordinary and cancellation caps apply. Durable per-session storage is 16 MiB/256 records; reserve 4096 bytes for cancellation per accepted operation. Never evict active/unknown records.

## Synthetic fixture

`cache/v1` uses distinct IDs `example.cache.desired.v1` and `example.cache.projection.v1`; actual enrollment supplies complete documents and calculated digests. Both schemas are closed `{capacity:integer[0..10],mode:enum[ephemeral,persistent]}`. Empty runtime effects still reserve an operation; no-op success requires fresh observe confirming exact desired projection and plan precondition. Never invoke apply or invent a revision.
