## Synthetic happy path

Synthetic status: request `{"target":"demo","driver_id":"example.synthetic","kind":"cache","schema_id":"example.cache.desired.v1","resource_id":"primary"}` returns `{"state":"present","revision":"r1","observed_at":"2025-01-01T00:00:00.000Z","projection":{"capacity":2,"mode":"ephemeral"}}`. Cache capacity 0..10 and mode `ephemeral|persistent` as in schemas.md.

The deterministic effect comparator is ascending Unicode scalar order on `(class,summary_id,destructive)` (false before true). Emit a resize effect exactly when desired capacity differs from observed capacity; emit a mode effect exactly when desired mode differs from observed mode. Effects contain only changed dimensions, in comparator order. Old full bridge plus old full keeper remains unchanged.

1. Launcher selects declarative; one-use authenticated attachment negotiates protocol 1 and exact six tools. Client validates deterministic JSON Schema and enrolled documents. `both` invalid; full mode retains eight legacy tools. Any requested-mode/protocol negotiation failure is an explicit refusal, never silent downgrade. Old keeper refuses declarative; new bridge refuses old keeper.
2. `driver_list` exposes enrolled metadata; `resource_status` observes fixture projection/revision `r1`.
3. `resource_plan` request `{"target":"demo","driver_id":"example.synthetic","kind":"cache","schema_id":"example.cache.desired.v1","resource_id":"primary","desired":{"capacity":4,"mode":"persistent"},"request_id":"AQEBAQEBAQEBAQEBAQEBAQ"}` returns `{"plan_id":"AAAAAAAAAAAAAAAAAAAAAA","digest":"0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef","expires_at":"2025-01-01T00:05:00.000Z","effects":[{"class":"cache.configure","summary_id":"cache.capacity","destructive":false},{"class":"cache.configure","summary_id":"cache.mode","destructive":false}],"precondition":"r1"}`. Digest is illustrative only, not a computed digest or test vector; compare output structure/order and precondition, not digest bytes. The corresponding distinct policy records are each delegated and non-destructive.
4. Apply request is `{"plan_id":"AAAAAAAAAAAAAAAAAAAAAA","request_id":"AQEBAQEBAQEBAQEBAQEBAQ"}`. Its successful typed result is `{"operation_id":"AgICAgICAgICAgICAgICAg","state":"SUCCEEDED"}`. The fixture's two effects are applied in order under CAS, changing `r1` to `r2` once. A no-op result after that transition uses fresh observation `{"verified":true,"projection":{"capacity":4,"mode":"persistent"}}` and revisions `{"applied":null,"delivered":null,"observed":"r2","adopted":null}` under exclusive ownership. No-op does not call apply or invent a revision.

`operation_read` reports evidence independently; adoption null absent enrolled verification. Same-live-session retries use durable idempotency. Attachment loss forbids reconnect and quarantines resource pending human inspection/fresh authorized launch. Times are UTC RFC3339 milliseconds.

Do not present JSON bodies as Ktav examples: Ktav encodes request/result payloads as strings, and these illustrative JSON snippets are not exact wire vectors. Successful application envelopes use `{ "result":<typed result>,"error":null }`; failures use `{ "result":null,"error":<typed error> }`. Operation states are uppercase. A no-op has no `applied` or `delivered` revision, has the actual fresh `observed` revision (null only under exclusive ownership), `adopted:null`, and a successful `result` with `verified:true` and the freshly observed desired projection. A subsequent no-op after the described CAS therefore observes `r2`; it does not invoke apply or fabricate a revision.

Before durable invocation-start/process call, proven failure means no invocation/effect. Once invocation may have started, outcome is unknown absent evidence.

### Chosen semantics, replacement rationale and remaining gaps

**INSPECTED / NOT EXECUTED:** The parent chose the proposed contract, not human approval or production readiness. P and S are separate implementations; shared schema canonicalization and digest do not imply whole-API equivalence. All present shapes and nested schemas are checked. Explicit types permit valid irrelevant keywords. Typeless finite-only nodes admit `enum` and/or `const` plus annotations; typeless closed objects require a valid closed shape and may also include `enum` and/or `const` and annotations. No other type-specific keywords are allowed in either form. Finite constraints apply to all values before object-only constraints. Reversed bounds are unsatisfiable only for the relevant type; extra required names make closed objects unsatisfiable. Admission does not prove satisfiability.

Obsolete strict schema negatives are replaced, not simply deleted:

- Mismatched keywords: `TestUnifiedLiteralVectors` asserts accepted irrelevant containers/scalars and nested nullable cases plus wrong-type and applicable-value failures; `TestUnifiedMalformedLiteralVectors` retains malformed irrelevant keyword and nested-schema negatives.
- Reversed bounds: `TestUnifiedLiteralVectors` admits object, array, string, inclusive and exclusive integer cases with nullable or other-type witnesses, and rejects relevant-type values; `TestUnifiedMalformedLiteralVectors` retains individually invalid bound negatives.
- Omitted empty object fields and extra required names: `TestUnifiedLiteralVectors` admits empty equivalents and typed/typeless extra-required shapes; it rejects extra properties and all object witnesses for the unsatisfiable shapes. `TestUnifiedMalformedLiteralVectors` retains duplicate required, open typed objects and unrequired declared-property negatives.
- Typeless boundaries: `TestUnifiedLiteralVectors` asserts exact finite intersection and mixed values, plus a closed object with a declared property and non-object witnesses; missing, malformed and extra property values fail. `TestUnifiedMalformedLiteralVectors` rejects other type-specific keywords on finite and closed nodes, including nested cases.
- Boolean and nullable boolean: root and nested literal witnesses cover valid irrelevant `uniqueItems`, `multipleOf`, `exclusiveMinimum` and `exclusiveMaximum`; malformed nested forms reject. Applicable array uniqueness and integer divisibility and exclusive-bound endpoints have independent positive and negative witnesses.

These are independent literal expected outcomes, not comparison of one validator against the other. `unifiedDigest` hashes the literal canonical schema with the domain and NUL directly, not through either validator. `checkUnifiedMalformed` also independently requires `CanonicalSchemaDocument` to reject before digest comparison; invalid JSON numbers need not have a canonical pin. `TestUnifiedIndependentPinsAndErrorClasses` checks wrong domain, missing NUL, stale document, identity and value errors. `TestUnifiedPinnedRequestAndProjection` supplies request and projection witnesses; no test execution is claimed.

**INFERRED — integration:** `internal/enrollmentrecord/record.go` calls P; `internal/enrollmentvalidator/references.go` calls S and checks digest binding. `internal/driverprocess/process.go` and `internal/immutableexec/immutableexec.go` use structural validation only, not pinned semantic validation. Isolated acceptance does not establish authenticated distribution, authorization, descriptor equality, runtime ID/digest/context enforcement or full v1 conformance. The partial broker and MCP fail-closed behavior remain separate concerns. Unsupported references, patterns, formats, composition and general JSON Schema are outside the chosen dialect, not missing dialect features. Future gated integrated acceptance must retain tampering, wrong ID/digest, invalid value, resource and projection adversaries, and independently reviewed authentication and authorization; no production connection is implied.

Compatibility and limitations: There is no automatic migration or rewrite. Unchanged documents keep canonical bytes and pins; changed schema documents require a new digest and enrollment. Preexisting standalone pinned raw admission gaps remain: P `ValidatePinnedValue` calls `ParseJSON` with a 65536-byte raw cap, while S canonicaljson permits 262144 raw bytes. A 65537-byte padded null is accepted by S and rejected by P with `ErrInvalid`. P rejects `-0`, while canonicaljson normalizes it to zero; an integer schema accepts it in S but P returns `ErrInvalid`. Shared schema canonicalization/digest is not whole-API equivalence. No parser changes or protocol frame broadening are implied; the separate 65536-byte protocol frame cap is unchanged. No local execution, checks, tests, lint or build were performed; no CI results currently exist, and public CI is for the parent only. No formal proof is claimed.

## Limits and status

Driver subprocess frames ≤65536 payload bytes excluding prefix; complete ≤65540. Broker Ktav payload ≤262144 excluding prefix. Desired/projection caps separate. Active limits: ordinary 32/session and 64 globally (queued/running/unknown); processes 64 ordinary globally and 16 emergency cancellation globally, at most 80 combined. Four ordinary plus one cancellation process per enrollment. Per-session storage is 16 MiB and 256 combined records inclusive; cancellation reserve 4096 bytes per operation. No separate 256-active global cap. Limits and lifecycle budgets are proposed, not implemented. Human review required for enrollment, artifact/schema distribution, OS identity, principal, target, sink, connector and adoption.
